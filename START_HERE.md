## Хочу использовать

Начни с программного reference на main: `npm ci`, `npm test`, `npm run demo:reference`. Это путь для изучения, воспроизведения и разработки. Он не означает готовность к реальным платежам или промышленным устройствам.

## Хочу исследовать

Выбери отдельный трек в RESEARCH_INDEX.md. Для CaPU × ATMAN нужен worktree на точном коммите: лаборатории ещё находятся в draft PR #103/#104, а не в main. Не объединяй ветки только ради уменьшения их числа.

## Хочу проверить результат

Открой [архив свидетельств](evidence/capu-atman/2026-09-05/README.md). Там сохранены полные JSON и журналы двух этапов в gzip без потери исходных байтов. Манифест различает хеш файла и digest внутри результата. Сохранение архива не является повторным прогоном.

v1 содержит 55 тестов; v2 — 28 тестов, то есть 14 сценариев на двух реализациях. Обычный автомат с теми же гарантиями прошёл сравнение так же успешно. Превосходство над ним не установлено.

## Что ещё не готово

PR #103/#104 остаются черновиками: native Codex-review был заблокирован лимитом, одобрения нет. Публикация документации и свидетельств не снимает этот запрет и не изменяет код кандидатов. HTTP-стенд использует один доверенный компьютер и тестовые подтверждения; исполнителя можно вызвать в обход контроллера.

## Как сохранять следующую работу

Один вопрос → одна рабочая ветка → точный исходный коммит → контроль и негативные случаи → результат и хеши → ревью → отдельное решение о включении в main. Исследовательские и отрицательные результаты не удаляются.
